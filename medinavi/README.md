# MediNavi — 강원 응급의료기관 지도

강원 응급의료기관 23곳과 인접 시·도(경기·충북·경북) 27곳, 모두 50곳을 네이버 지도에 표시하고, 현재 위치에서 선택한 병원까지의 자동차 경로·예상 시간·거리를 보여 줍니다.

- 배포 주소: <https://medinavi.onrender.com>
- 배포 방식: Render Web Service (`main` 브랜치에 커밋하면 자동 배포)

## 1. 파일 구성

| 파일 | 하는 일 |

| `frontend/symptom-recommend.js` | 증상 기반 추천: AI 증상 분류 → 확인창 → 규칙표로 역량 판정 → 1~5순위 (서버 `/api/symptom/parse`, `/api/rules` 사용) |
| `data/recommendation_rules.json` | 표준지침(2023) 기준 분류별 기관 등급·수용 조건·Pre-KTAS 중증/경증 기준 |
| `tools/fetch_realtime_sample.py` | 실시간 병상·중증질환 API 응답 항목을 확인하는 샘플 조회 스크립트 |
| `tools/fetch_messages_sample.py` | 병원이 올린 응급실·중증질환 메시지(공지) 응답을 확인하는 샘플 조회 스크립트 |
| `data/hospitals.json` | 강원 23곳 + 인접 시·도 27곳 의료기관의 항목명·값·출처·조회 시점, 등록 진료과목(`departments`) |
| `data/regions.json` | 병원을 찾는 지역: 강원 전체 + 인접 시·도 14개 시·군(경기 포천·연천·의정부·남양주·구리·양평·여주·이천, 충북 충주·제천·단양, 경북 울진·영주·안동) |
| `tools/refresh_hospitals.py` | 병원 목록(강원 + `regions.json`의 인접 시·군 지정 응급의료기관)을 API로 다시 받아 바뀐 곳(신규·삭제·유형·전화·좌표)을 보여주고 `--write`로 반영, 외상센터 여부 표시 |
| `tools/eval_symptom.py` | AI 증상 분류를 `tests/symptom_cases.json`(50문장)으로 채점 (12월 평가 "조건 추출 정확도") |
| `tests/` | 자동 시험: 서버 단위 시험(`test_server.py`), 화면 시나리오 시험(`js/frontend.test.js`), 시험용 가짜 모듈(`stubs/`) |
| `tools/fetch_departments.py` | 기관 ID로 국립중앙의료원 기본정보를 조회해 등록 진료과목을 `hospitals.json`에 합치는 스크립트 |
| `requirements.txt` | 서버 실행에 필요한 Python 라이브러리 |
| `.env.example` | 실제 인증정보가 없는 환경변수 입력 양식 |
| `server.ipynb` | 개발용 노트북 (Git 업로드 제외 대상) |

## 2. Render 배포 설정

Render 대시보드의 **medinavi** 서비스 → **Settings**에 다음 값이 들어가 있어야 합니다.

| 항목 | 값 |
| --- | --- |
| Source / Branch | `lys0348-cmd/myailab` / `main` (2026-11-19 `yunsung-yonsei/myailab`에서 이전) |
| Language | Python 3 (`yarn` 아님) |
| Root Directory | `medinavi` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn app:app --host 0.0.0.0 --port $PORT --no-access-log` |
| Auto-Deploy | On Commit |

**Environment** 메뉴에는 다음 두 환경변수를 넣습니다. 값은 GitHub·채팅·화면 코드에 넣지 않습니다.

- `NAVER_MAPS_CLIENT_ID`: 네이버 Maps 인증 ID
- `NAVER_MAPS_CLIENT_SECRET`: 네이버 Maps 인증 비밀키
- `EMERGENCY_API_KEY`: 공공데이터포털 국립중앙의료원 응급의료기관 정보 조회 서비스 인증키 (실시간 병상·중증질환 정보). 없으면 해당 정보만 "확인 필요"로 표시되고 나머지 기능은 정상 동작합니다.
- (선택) `NAVER_GEOCODING_CLIENT_ID`, `NAVER_GEOCODING_CLIENT_SECRET`: 주소 검색용 키를 별도 애플리케이션으로 발급받은 경우에만 넣습니다. 없으면 위 Maps 키를 그대로 사용합니다.

`--no-access-log`는 좌표가 포함된 요청 주소를 접속 로그에 남기지 않도록 하는 옵션입니다.

## 3. 외부 설정 확인

- 네이버 Maps 애플리케이션에서 **Web Dynamic Map**, **Directions 5**, **Geocoding**(출발지 주소 검색)을 사용할 수 있어야 합니다.
- 네이버 Maps의 Web 서비스 URL에 `https://medinavi.onrender.com`(로컬 시험 시 `http://localhost:8000`)이 등록되어야 지도가 열립니다.
- 웹 지도는 `frontend/index.html`(백업 화면은 `index_classic.html`)의 공개 Client ID를 사용합니다. Render 환경변수의 인증정보도 같은 Maps 애플리케이션 것이어야 합니다.
- Render 무료 인스턴스는 한동안 접속이 없으면 잠들어, 첫 접속이 30초~1분 정도 느릴 수 있습니다. 잠들면 실시간 정보 저장분과 호출 제한 기록도 초기화됩니다. **발표·시연 직전에는 사이트에 미리 한 번 접속**해 두세요.

## 4. 자동 시험과 운영 점검

**자동 시험 (GitHub Actions)**: `medinavi` 폴더를 고친 PR을 올리면 `.github/workflows/medinavi-tests.yml`이 자동으로 실행됩니다. PR 화면에 빨간 X가 뜨면 합치기 전에 원인을 확인하세요.
- 실제 패키지로 서버가 켜지는지 (오타로 인한 시작 실패 방지)
- 서버 단위 시험: 실시간 정보 정리·저장, 증상 분류 검증, 길찾기 저장, 호출 제한, 주소 검색, 규칙표 이름·표준지침 구조 검사
- 화면 시나리오 시험: 조건 검색, 실시간 표시, 증상 추천, 출발지 주소, 실시간 실패 시 동작
  - 가짜 화면으로 공통 스크립트를 시험하므로 요소가 단순한 `index_classic.html`로 돌리고, 기본 화면(`index.html`)은 같은 요소 id·같은 스크립트 버전을 쓰는지 따로 검사합니다. 기본 화면만의 동작(`ui_joonghee.js`)은 사이트에서 직접 확인합니다.
  - 공통 스크립트를 고치면 두 화면의 `?v=` 숫자를 같이 올립니다 (시험이 다르면 실패).

내 PC에서 직접 돌리려면 `medinavi` 폴더에서 실행합니다 (외부 접속 없이 동작).

```powershell
python -m unittest discover -s tests -p "test_*.py"
node tests/js/frontend.test.js
```

**호출 제한**: 누구나 부를 수 있는 API는 IP별 1분 호출 수를 제한합니다 (길찾기 120, 주소 검색 20, 증상 분류 10, AI 결과 설명 10, 실시간 30). 같은 출발지(약 10m)에서 같은 병원으로 가는 길찾기는 5분 동안 저장값을 다시 씁니다.

**정기 점검 (한 달에 한 번 권장)**
1. `python tools/refresh_hospitals.py`로 병원 목록 변경 확인 → 필요하면 `--write`로 반영 → 새 기관이 있으면 `python tools/fetch_departments.py --write`
2. 바뀐 `data/hospitals.json`을 PR로 올립니다.

**AI 증상 분류 채점**: `python tools/eval_symptom.py` (배포 사이트 기준, 약 6분). 분류마다 정확도와 틀린 문장을 보여주고 결과를 `data/`에 저장합니다.

## 4-1. 내 PC에서 서버 띄우기 (선택)

`medinavi` 폴더를 VS Code로 열고 터미널에서 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`.env.example`을 복사해 이름을 `.env`로 바꾸고 두 값을 입력한 뒤 서버를 실행합니다. 파일명은 `.env.txt`가 아닌 `.env`입니다.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000 --no-access-log
```

크롬에서 <http://localhost:8000/>을 엽니다. 종료는 `Ctrl+C`입니다. macOS/Linux에서는 실행 파일 경로를 `.venv/bin/python`으로 바꿉니다.

## 5. 기능 확인 순서

1. 병원 50곳의 목록·핀과 기본정보가 보이는지 확인합니다. 없는 항목은 `확인 필요`, 좌표가 없는 기관은 목록에 `좌표 없음`으로 표시합니다.
2. 지도 준비 후 위치를 한 번 요청하고 빨간 현재 위치 점을 표시합니다. 실패하면 `내 위치` 버튼으로 재시도합니다.
3. 병원을 누르면 초록색으로 약 두 배 커진 병원 핀, 빨간 출발지 점, 초록 도로 경로가 함께 보입니다.
4. 경로 옆 검은 상자에 `약 N분`과 `N.Nkm`가 두 줄로 표시됩니다.
5. 다른 병원을 누르면 경로·상자가 교체됩니다. `전체 보기`는 경로·상자를 지우고 전체 병원 핀을 복원합니다.

휴대폰에서는 `https://medinavi.onrender.com`으로 접속합니다. 위치 기능은 HTTPS 주소에서만 동작합니다.

### 출발지 주소 지정

- 출발지는 기본으로 현재 위치(빨간 점)를 사용합니다. **출발지 주소**에 주소를 입력해 검색하고 후보를 고르면 그 지점(파란 핀)이 출발지가 됩니다.
- 조건 검색, 병원 선택 시 길찾기, 지도 범위는 모두 지정한 출발지를 기준으로 동작합니다. `내 위치`를 누르면 현재 위치로 돌아갑니다.
- 네이버 Geocoding은 **주소**를 좌표로 바꾸는 기능이라 `강릉시 강릉대로 33`처럼 시·군과 도로명·건물번호를 넣어야 잘 찾습니다. `강릉시청` 같은 장소 이름은 찾지 못할 수 있습니다.
- 입력한 주소는 서버 로그에 남기지 않습니다.

### 실시간 병상·중증질환 수용 가능 정보

- 서버가 국립중앙의료원 **응급실 실시간 가용병상정보 조회**와 **중증질환자 수용가능정보 조회**를 강원 단위로 한 번에 불러오고, 90초 동안 저장해 둡니다. 화면은 2분마다 새로 불러옵니다.
- 검색 결과에는 E-Gen 종합상황판과 같은 **가용/전체** 형식으로 `응급실 16/21 (원활) · 3분 전`처럼 표시하고, 결과 왼쪽에 색 띠를 붙입니다.
  - 혼잡도 기준(팀 결정): 가용/전체 **50% 이상 원활(초록), 20~50% 보통(노랑), 20% 미만 혼잡(빨강)**, 0 이하는 **포화**(음수는 대기 환자 수)
  - 병원 갱신 시각이 30분을 넘으면 `갱신 지연`으로 표시합니다.
  - 실시간 병상 정보는 결과의 순서나 제외에 쓰지 않습니다 (이동시간순 유지).
- 병원 상세정보에는 값이 있는 병상 항목, 시설·장비(CT·MRI·혈관촬영기 등), 중증질환 27개 항목을 `가능 / 불가 / 확인 필요`로 묶어 보여줍니다. 실제 응답의 `N1`·`불가능`은 불가로, `정보미제공`은 확인 필요로 처리합니다.
- 항목 정의는 공공데이터포털 활용가이드(V13) 기준입니다. 응급실 전체 병상 `hvs01`은 가이드에 정의가 없지만, 2026-11-12 E-Gen 종합상황판의 응급실 '가용/전체' 중 전체 값과 일치함을 확인해 사용합니다. 다른 `hvs` 항목은 쓰지 않습니다.
- 격리병상은 E-Gen(병원 전체 격리병상)과 기준이 달라 `응급실 내 음압격리병상`처럼 이름을 분명히 표시합니다.
- **중증질환 검색 조건**: 조건 검색에서 27개 항목 중 하나를 고를 수 있습니다. 병원이 `가능`으로 입력한 곳만 길찾기해서 결과로 보여주고, `불가`는 제외한 수를 안내하며, `정보미제공`·실시간 정보 없음은 **중증질환 수용 가능 여부 확인 필요** 목록에 따로 보여줍니다.
- 병상이 있거나 '가능'으로 표시돼도 실제 수용 여부는 병원에 확인해야 합니다.

### 증상 기반 추천 (표준지침 2023 기준 · 강원 지침 확인 전)

- 환자 상태와 증상을 문장으로 입력하면 AI(`OPENAI_API_KEY`)가 **정해진 증상 분류 중 하나로 나누기만** 합니다. 진단명이나 중증도는 판단하지 않고, 근거로 보여주는 표현은 입력 문장에 실제로 있는 단어만 남깁니다.
- 확인창에서 증상 분류, **Pre-KTAS 등급(구급대원 평가)**, 분류별 확인 항목, **환자 나이**, 최대 이동시간을 확인·수정한 뒤 추천을 실행합니다. AI가 실패하면 분류를 직접 골라 추천받을 수 있습니다.
- **나이**: 숫자와 단위(세/개월)로 직접 입력합니다. AI는 문장에 나온 나이만 채우고(예: 생후 2개월 → 2개월, 5살 → 5세) 추측하지 않습니다. 나이가 있으면 만 18세 미만이면 소아로 자동 표시되고, 나이를 모르면 '소아로 보기' 체크박스를 씁니다. 나이별 지침 기준은 규칙표 `when.age_months_lt`(개월 수 미만)로 적습니다. 예: 생후 3개월 미만 발열은 소아청소년과 필수(지침 p.316).
- 규칙표 `data/recommendation_rules.json`은 소방청 「119구급대원 현장응급처치 표준지침(2023 개정본)」의 이송병원 선정지침을 **공공데이터로 확인할 수 있는 범위에서만** 옮긴 것입니다. 분류마다 지침 쪽수를 적어 두었고, 화면에도 "적용 기준: … (표준지침 p.○○)"로 보여줍니다.
  - **중증/경증**: Pre-KTAS 1·2단계 또는 미입력은 중증, 3~5단계는 경증 기준을 씁니다 (지침 p.61: 과소분류보다 과분류). 심정지·절단은 등급과 관계없이 같은 기준입니다.
  - **기관 등급**: 기준마다 최소 등급이 있습니다 (`any` 응급의료기관 / `local_institution` 지역응급의료기관 이상 / `local_center` 지역응급의료센터 이상 / `trauma_center` 권역외상센터). 두 분류면 더 높은 등급을 씁니다.
  - **확인 항목**: 흉통 "ST분절 상승 확인", 경련 "지금도 경련 중·임산부", 발열 "미숙아 등 과거력(소아)", 분만 "고위험·미숙아 분만·만삭 분만"처럼 지침이 목적지를 나누는 조건은 확인창의 체크 항목으로 고릅니다.
  - `required`: 모두 `가능`이어야 추천 / `required_any`: 하나 이상 `가능`이면 추천 / `reference`: 판정에 쓰지 않고 근거로만 표시. 모든 환자에게 응급실 일반 병상 가용(`common_required`)을 확인합니다.
- 결과 묶음
  - **1~5순위**: 등급과 조건을 모두 충족, 이동시간순
  - **의료지도 필요**: 조건은 맞지만 지침 등급보다 낮은 가까운 기관. 지침의 "지역별 여건에 따라 의료지도 등을 받아 치료 가능한 가까운 지역응급의료기관으로 이송할 수 있다"에 따른 것입니다.
  - **지금 수용 어려움 / 일부 조건만 일치 / 조건 확인 필요**: 이전과 같습니다.
- **두 번째 분류 정리**: AI가 두 분류를 답해도 서버가 규칙표 `secondary_rules`로 한 번 더 정리합니다. 열·의식 저하·호흡곤란·실신(`consequence`)은 다른 문제의 결과인 경우가 많아 다른 분류와 함께면 그 분류만 남기고, 외상+토혈·혈변, 외상+복통, 토혈·혈변+복통(`dominates`)은 앞쪽 하나만 씁니다. 예: "사고 후 의식이 흐려짐"은 외상 하나, "경련하며 열이 남"은 경련 하나.
- **데이터가 없어 전용 조건을 뺀 분류**: 뇌졸중(혈전용해 가능 기관), 정신과(지정 정신의료기관), 뱀 교상(항독소 보유)은 핵심 조건 정보가 API에 없어, 분류는 남기되 비외상 일반 기준만 적용하고 제외 사유와 지침 안내를 함께 보여줍니다. 소아 중증 호흡곤란의 "소아 중환자 치료 가능" 조건도 같은 이유로 빼고 안내만 합니다.
- **인접 시·도 병원**: 표준지침은 '가까운 기관'만 정하고 시·도 경계 조건이 없으며, 중증외상은 다른 시·도 권역외상센터가 더 가까우면 그쪽으로 이송할 수 있습니다 (p.53, p.325). 그래서 철원·원주·삼척 등 경계 지역에서 더 가까울 수 있는 경기·충북·경북 병원도 후보에 넣고 '타 시·도(경기도)'로 표시합니다. 실시간 정보는 목록에 그 시·도 기관이 있을 때만 시·도 단위로 함께 조회합니다. 후보가 늘어도 길찾기 호출이 늘지 않도록, 직선거리가 '시간 제한(분) × 2km'를 넘는 병원은 길찾기를 하지 않습니다.
- **중증외상**: 권역외상센터가 목적지입니다. 외상센터 지정 정보는 `python tools/refresh_hospitals.py --write`로 `hospitals.json`에 `trauma_center`를 반영해야 하며, 반영 전에는 등급을 '확인 필요'로 표시합니다. 가장 가까운 외상센터가 30km 또는 60분을 넘으면 헬기 이송·의료지도 안내를 띄웁니다 (지침 p.54, p.325).
- 지역 이송지침이 있으면 그것이 우선입니다 (지침 p.5). 2026년 강원 이송지침을 확인하면 규칙표를 맞춰 고쳐야 합니다. 화면에는 항상 "표준지침(2023) 기준 · 강원 지침 확인 전"과 "최종 판단은 구급대원·의료진" 안내가 붙습니다.

### 바로 전화 걸기

- 조건 검색·증상 추천 결과(1~5순위, 의료지도 필요, 지금 수용 어려움, 일부 조건만 일치, 확인 필요)와 병원 상세의 응급실 연락처에 **📞 전화** 버튼이 붙습니다. 휴대폰에서 누르면 전화 앱이 응급실 번호(`dutyTel3`, 없으면 대표번호 `dutyTel1`)를 채워서 열립니다. 통화 버튼은 사용자가 직접 눌러야 걸립니다.
- **시험 모드**: 실제 병원에 전화가 가지 않게 버튼을 확인하려면 주소 끝에 내 휴대폰 번호를 붙여 접속합니다.
  - 예: `https://medinavi.onrender.com/?call_test=01012345678`
  - 그 탭에서는 모든 전화 버튼이 병원 대신 그 번호로 걸리고, 버튼이 주황색으로 바뀌며 화면 위에 "전화 시험 모드" 알림이 계속 보입니다.
  - 번호는 코드·서버·GitHub에 남지 않고 그 탭에만 저장됩니다(탭을 닫으면 사라짐). 주소창에서도 바로 지웁니다.
  - 다른 사람이 보낸 주소로 엉뚱한 번호(유료 060 등)에 걸리지 않도록 휴대폰 번호(010·011·016·017·018·019)만 받습니다.
  - 끄기: 알림의 `시험 모드 끄기` 버튼, 또는 `?call_test=off`로 접속.

### 등록 진료과목 검색

- 조건 검색의 **등록 진료과목**은 선택 조건입니다. 고르면 기관 유형과 진료과목으로 후보를 먼저 줄인 뒤 길찾기로 이동시간을 비교합니다.
- 결과에는 `○○과 등록 확인 · 현재 수용 여부 확인 필요`로 표시합니다. 등록 진료과목은 현재 진료·응급환자 수용 가능 여부를 뜻하지 않습니다.
- 진료과목 자료가 비어 있는 기관은 결과에서 빼고 **진료과목 확인 필요** 목록에 따로 보여줍니다.
- 병원마다 이름이 다른 같은 과목은 `app.py`의 `DEPARTMENT_ALIASES`에서 묶습니다 (예: `구강안면외과` → `구강악안면외과`).
- 진료과목 자료를 새로 받으려면 `medinavi/.env`에 `EMERGENCY_API_KEY`를 넣고 `python tools/fetch_departments.py --write`를 실행합니다. 먼저 `--sample 3`으로 몇 곳만 확인할 수 있습니다.

## 6. 코드와 변수 설명

`frontend/map.js`는 기존 코드의 모든 줄·변수명을 유지하고, `window.hospitalRouteView`를 부르는 연결 코드와 한글 주석만 추가했습니다. 추가 동작은 `frontend/hospital-route-view.js`에 모아 두었으며, 기존 거리 조회 응답의 `path`를 재사용하므로 경로 표시만을 위한 중복 API 호출은 없습니다.

| 이름 | 뜻 |
| --- | --- |
| `selectedHospital` | 현재 선택한 병원 |
| `locationMarker` | 기존 빨간 현재 위치 점 |
| `routeLine` / `routeLabel` | 경로선 / 시간·거리 상자 |
| `hospitals` | 기관 ID별 병원 핀과 원래 모양 |
| `register` / `select` | 원본 핀 전달 / 선택 병원 변경 |
| `draw` | 받은 도로 좌표로 경로 표시 |
| `locationReset` / `locationReady` | 위치 재조회 시 정리 / 위치 확인 후 경로 조회 |
| `showAll` | 경로 정리와 전체 병원 핀 복원 |

병원 JSON은 저장 당시 정보이며 현재 수술·수용 가능 여부를 판단하지 않습니다. 경로는 `trafast` 옵션의 일반 자동차 기준 예상이며, 구급차 특례 주행이나 주행 중 자동 재탐색은 포함하지 않습니다.
